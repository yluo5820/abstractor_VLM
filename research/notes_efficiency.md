# Low-compute VLM efficiency ideas: novelty audit

Audit date: 2026-09-14. This note is a targeted primary-source audit, separate from the 300-title screening in `research/corpus/screened_efficiency.json`. Nineteen selected papers were inspected at differing depths, recorded in `sources_efficiency.json`. “Full-text sections” means reading relevant methods/experiments/limitations, not claiming every page was read. These are hypotheses for a project, not verified new results or promises of publication.

## Recommendation

The safest efficiency project is a **mechanistic study of what compression does to spatial relations**, with a small inference-only mitigation. The runner-up is a **calibration study of compression-induced harm to difficult evidence groups**. Generic OCR-aware pruning, adaptive zooming, confidence routing, multi-turn token recovery, and measuring real latency are already substantially occupied. A paper would need the specific controlled experiment and empirical result below; merely adding a new attention score or conformal threshold is unlikely to suffice.

## Candidate E1: Does object-focused token pruning discard the background needed for spatial relations?

**Research question.** At the same visual-token budget, do methods that retain object content preferentially erase distributed ordering information, producing a larger deficit on relational questions than on object/attribute questions about exactly the same image?

**Why this is plausible, and what is actually new.** Cui et al. already show that spatial ordering is encoded beyond object regions. FEATHER already shows localization failures and fixes positional selection bias. The proposed contribution is the interaction between these mechanisms and deployed token compression: a controlled causal test of *content preservation versus relation preservation*, followed by a budget-matched remedy. Do not claim discovery of background spatial information, spatial pruning failure in general, or a new spatial benchmark simply because synthetic images are used.

**Core experiment.** Build 400–600 paired layouts using an existing controlled-scene generator: horizontal/vertical object swaps preserve object identities and attributes while changing the answer to a relational question. Ask one object/attribute question and one relational question per scene. Vary spacing, background texture, distractors, object count, and location. Hold out layout families and object identities, rather than randomly splitting nearly identical renders. Report results on all scenes, plus the subset on which full inference answers both members correctly. The latter is a diagnostic denominator, never the advertised benchmark accuracy.

**Mechanism test.** Keep object tokens fixed while changing which background tokens survive. At equal token count, compare background strips aligned with the relevant spatial axis against random background, isotropic uniform background, and salience-only background. Use the original visual-token grid/positional coordinates. Run interchange interventions on cached representations to test whether restoring ordering-bearing background tokens recovers relation answers more than matched random restoration. Treat linear probes as suggestive; causal replacement and actual QA behavior supply the main evidence.

**Practical method, only if the mechanism holds.** Add a small structured spatial-coverage quota to an existing pruner, with direction inferred from question text and token grid coordinates. Compare a query-agnostic quota and a question-conditioned quota. Ground-truth object masks may be used for diagnosis and an oracle upper bound; the deployed policy must use no ground-truth mask or answer. If selecting strips requires a detector or another VLM, charge its entire cost and reconsider the method.

**Models/data.** Start with Qwen2.5-VL-3B for feasibility and short exact-match answers. Reproduce the mechanism on Gemma-3-4B or Qwen2-VL-7B if resources permit; Cui et al. studied the latter two families. Natural-image checks: What'sUp, a spatial GQA subset, and the COCO-spatial setup from Cui et al.; reuse official licenses/splits. The final claim should not rest on synthetic data alone. Model and dataset availability must be verified in the setup pilot.

**Baselines.** Full inference; random/uniform retention; FastV; FEATHER; one modern redundancy method (ApET if implementation is compatible); ET-Prune or PosPrune for spatial/evidence protection; object-only oracle with the same budget. Minimum viable project uses three compatible pruners on one model, not six fragile ports. Full attention materialization must not be enabled only for competitors.

**Metrics.** Exact answer accuracy, paired-counterfactual accuracy (both members correct), identity-versus-relation accuracy gap, compression-induced wrong flips, object/attribute accuracy retained, intervention recovery rate, actual visual-token count, peak memory, prefill and end-to-end latency. Pair/bootstrap by original scene/image. Compare at equal token count *and* show equal-latency curves; record preprocessing, vision encoding, selection, decoding, and overhead separately. Do not call a lower token count a speedup.

**Compute plan (estimates, not measured).** One 24 GB GPU is the target for the 3B short-answer pilot; allow a 48 GB option for 7B or activation-heavy runs. About 8,000–15,000 short inference calls plus a bounded intervention subset: **25–70 GPU-hours**, including a 2× rerun/debug allowance; **4–8 GPU-hours** for the initial pilot. This assumes roughly 1–4 seconds/call after warmup; high-resolution images or unfused attention can exceed it. Store selected layer activations only for a few hundred examples and process interventions in batches; do not save every layer for the full corpus. CPU rendering/probe fitting can proceed while waiting for ICE/cluster slots.

**48-hour pilot and kill criteria.** First get 100 layout pairs, one 3B model, and full/uniform/one attention pruner running. Use ≤64 output tokens. Continue only if (i) full pair accuracy is at least 70% on the intended task; (ii) the compressed relation deficit exceeds its object/attribute deficit by roughly 8 percentage points at a useful budget; and (iii) matched background restoration recovers materially more failures than random restoration. Kill the proposed *method* if ordinary uniform retention matches it, even if the diagnosis remains a good course result. Kill the research direction if the effect disappears under layout-held-out evaluation or only exists at a budget that destroys the base task.

**Publication risk.** Moderate to high novelty risk, but a strong falsifiable question. The valuable outcome is a replicated causal compression failure with a precise operating regime, not a universal faster VLM claim. A conference-sized extension would need multiple architectures, natural images, and a cheap mitigation with measured speed.

## Candidate E2: Can a compressed VLM preserve a declared error budget for fragile evidence groups?

**Research question.** Can a cheap resolution/pruning policy save measured time while bounding the *additional* errors caused by compression separately for small text and spatial-relation inputs, rather than satisfying only an aggregate quality target?

**Exact delta.** ET-Prune's “risk-calibrated” budget is an evidence-entropy/density heuristic with hyperparameters calibrated on a held-out subset. LazyMCoT calibrates recall of examples that benefit from extra grounding. CARES predicts sufficient resolution. The break-even study evaluates conditional quality/latency. This project combines a different estimand—one-sided, group-specific compression harm—with simultaneous finite-candidate validation and shift stress tests. The statistical technique is established prior work; novelty would come from showing that commonly reported aggregate retention hides predictable, recoverable group failures and delivering a reusable evaluation protocol.

**Define the loss first.** For a frozen full model F and compressed policy P, use h(x,y)=1[F(x)=y and P(x)≠y]. Report its expectation on all examples and, separately, conditional on full-correct examples. Also report net accuracy change: pruning can fix some full-model mistakes, which must not cancel destructive flips when assessing preservation. A 2% target on h does not mean 98% absolute model accuracy.

**Groups and splits.** Predeclare a small number of machine-observable groups: text size/density bins estimated by a fixed lightweight OCR or edge detector, and relation versus nonrelation question types. Gold boxes can annotate analysis bins but cannot drive deployment. Partition by image identity; use training/development, held-out calibration, and untouched test. Hold out one dataset/rendering family for a separate shift test. Under shift, report measured target violations and recalibration cost; claim no distribution-free guarantee against arbitrary shifts.

**Calibration.** Freeze a finite family of policies—e.g. three resolution caps crossed with several thresholds from an already-trained cheap predictor. Choose the fastest policy whose one-sided binomial upper confidence bound for h is below the declared target in every prespecified group, with multiplicity correction across policies and groups. This is simple, transparent, and does not require monotonic correctness as visual budget grows. Do not apply ordinary monotone conformal-risk formulas directly to non-monotone VLM accuracy. Under i.i.d./exchangeable matching populations and the stated candidate/selection protocol, the statistical claim concerns group population risk, not correctness of individual answers. Keep a full-inference fallback.

**Data/models/baselines.** Qwen2.5-VL-3B first; Qwen3-VL-2B/4B or a second 4B architecture if its checkpoint/implementation is available. TextVQA and ChartQA or OCRBench-v2, plus a compact spatial set. Use about 1,000–2,000 calibration examples and 1,000–2,000 held-out test examples, reducing group count if bins are sparse. Baselines: fixed pixel budget, image-size rule, CARES-style predictor if released weights are usable, ET-Prune if a compatible implementation exists, a global calibration threshold, and group calibration. A learned proxy should be trained on cached outputs and frozen before calibration; avoid training the VLM.

**Metrics.** Absolute task accuracy; destructive and beneficial flip rates; per-group error upper bounds and empirical violations; average/p95 measured end-to-end time; memory; fallback fraction; calibration sample cost; frontier of excess-harm target versus time. Include a proxy-overhead ablation. Small count bounds can force every input to full inference; this is an informative feasibility result, not a reason to omit uncertainty.

**Compute plan (estimates, not measured).** Cache roughly 15,000–30,000 short-answer outcomes across a few resolution policies, fit/calibrate tiny predictors on CPU, then benchmark only locked policies. **20–60 GPU-hours** for a 3B study, **40–100 GPU-hours** with a second model; **4–8 GPU-hours** for a pilot. Extra high-resolution OCR calls can double this. Set a hard per-image pixel/token cap and output-length cap before downloading full benchmarks. Queue-friendly jobs can be 30–60 minutes with resumable JSONL outputs.

**48-hour pilot and kill criteria.** On 300–500 images, run full and two lower-resolution settings and cache correctness/cost. Continue only if (i) oracle policy savings are ≥20% end-to-end at a plausible harm target; (ii) global policies hide at least one reproducible group deficit; and (iii) a cheap policy retains useful savings after its own overhead. If a 2% risk target needs more calibration data than the course can support, transparently use a 5% target for the course study. Kill method novelty if group calibration merely returns full inference or shows no advantage over the fixed image-size rule; retain a rigorous negative result only if it demonstrates a meaningful reproducibility/feasibility issue.

**Publication risk.** High: applying existing calibration to VLMs alone is incremental. Stronger if the same failure occurs across datasets/models, calibration beats aggregate tuning at matched measured cost, and the shifted-data failure boundaries are documented. Do not pitch it as the first conformal VLM router.

## Directions deliberately not promoted

- “Keep tiny OCR evidence while pruning the rest”: ET-Prune is a direct collision from August 2026.
- “Let confidence choose whether to zoom”: ViRGo and LazyMCoT are direct collisions.
- “Measure speed rather than FLOPs”: the August break-even study already formalizes the core issue.
- “Restore tokens when later questions need another region”: SparseVILA, MetaCompress, and September CONDUIT substantially overlap.
- Generic reasoning-budget routing: no defensible specific gap emerged from this targeted branch; long chain generation also makes a class compute budget less predictable. Prefer short-output perception/relation experiments.

## Practical feasibility assumptions

All GPU-hour ranges are planning estimates derived from call count times a rough 1–4 seconds per short call and an allowance for repeats; they are not published benchmarks. Actual ICE/PACE allocations, GPU types, availability, quotas and queue times were not checked by this subtask. A one-GPU, checkpointable inference design is intentional. A “48-hour pilot” is elapsed project time, not 48 reserved GPU-hours. Keep training optional and postpone any 7B/8B or long-video sweep until one-model results justify it.
